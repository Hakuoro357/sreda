# `docs/done/` — Weekly archive завершённых задач

## Структура

- `index.md` — точка входа: список weekly-файлов + status matrix с ссылками
- `2026-WNN.md` — один файл на ISO-неделю (понедельник-воскресенье)

## Workflow

1. **Pending задачи** живут в `docs/tomorrow-plan.md`.
2. Когда задача выполнена — помечаем `✅ DONE YYYY-MM-DD` (плюс хеш коммита если применимо).
3. **В конце дня (или раз в неделю)** переносим DONE-секцию **целиком** в соответствующий `docs/done/2026-WNN.md`:
   - Файл недели создаётся при первом DONE этой недели
   - Сохраняем содержимое **дословно** (без перефразирования)
   - Внутри weekly-файла — секции группируются по дате (Sub-header `## YYYY-MM-DD`)
   - Между разделами разной даты — разделитель `---`
4. После переноса — добавить запись в `index.md` (если новая неделя) и обновить status matrix если задача там фигурирует.

## Naming ISO weeks

ISO 8601 weeks: понедельник = первый день, неделя содержащая 4 января = W01.

Примеры (для 2026):
- `2026-W17` = 20-26 апреля
- `2026-W18` = 27 апреля – 3 мая
- `2026-W19` = 4-10 мая

Чтобы определить неделю даты — `date -d '2026-05-04' +%G-W%V` или Python `datetime.date(2026, 5, 4).isocalendar().week`.

## Что переносить, что нет

- ✅ Полностью DONE секции — целиком
- ✅ DONE подпункты в mixed-state разделах — только подпункт (структура раздела остаётся в `tomorrow-plan.md` с pending частями)
- ❌ Pending / DEFERRED / blocked задачи — остаются в плане
- ❌ Не оставлять в `tomorrow-plan.md` «✅ DONE → see archive» строки. Полное удаление + ссылка идёт через `index.md`.

## Запрет на перефразирование

Архив — исторический документ. Любое DONE-описание копируется **символ в символ** из `tomorrow-plan.md`. Включая опечатки, разговорный тон, ссылки на коммиты. Это защищает от drift'а памяти при post-hoc редактировании.
