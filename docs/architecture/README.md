# Архитектурные доки Среды — индекс + отслеживание актуальности

Это «склад» обзоров важных механизмов Среды. Цель — чтобы механизм можно было понять по
**доку рядом с кодом**, не копаясь в исходниках, и чтобы доки **не протухали**, когда меняется код.

## Как это работает

- Важный механизм → один обзор-док здесь, в `docs/architecture/`, + строка в таблице ниже.
- Каждый отслеживаемый док в шапке несёт:
  - `**Source code:**` — файл(ы)-ядро механизма (отслеживаются на актуальность);
  - `**Related code:**` (опц.) — смежные файлы, НЕ отслеживаемые (их изменение даёт лишь
    мягкий сигнал-пометку, см. `scripts/affected_docs.py`);
  - `**Verified-against:** \`<sha>\`` — git-коммит sreda, на котором док сверен с кодом.
  - Пути в `Source code`/`Related code` — в бэктиках, через прямой слэш; токен берётся в карту,
    если содержит `/` или `.` (путь или файл с расширением). Файл без расширения в корне
    (`Dockerfile`/`Makefile`) писать с префиксом `./`, иначе он не попадёт в карту.
- **Проверка:** `python scripts/check_docs_freshness.py` (из корня репо). Для каждого
  enrolled-дока: если `Source code` менялся ПОСЛЕ `Verified-against` → **STALE** (exit 1).
- **CI:** проверка гоняется на push в `main` и на PR; при STALE — **красный** (сигнал, решение
  владельца 2026-06-27: соло-разработчик, branch-protection НЕ вводим — красный `main` достаточен).
- **Дисциплина:** меняешь документированный код — перечитай док, поправь при расхождении,
  обнови `Verified-against` на текущий HEAD. Тогда CI снова зелёный.
- **Enrollment opt-in:** док отслеживается, только если есть ОБА поля. Легаси-доки с
  `Source code`, но без `Verified-against`, — НЕ валят проверку (постепенный бэкфилл).

## Бэкфилл (кандидаты на enroll — по важности)

Постепенно завести обзор-доки + enroll для ключевых механизмов:
- планировщик/ReAct: депрекейт plan-execute, текущий путь ReAct (эпик #191);
- privacy/mutation guard на границе tool/DB (#196, #24);
- durable-персист ReAct + checkpoint (#193);
- провайдеры/роутинг моделей (planner/chat/composer; #151/#175/#184);
- безопасный рестарт + деплой (`safe_restart`, deploy private-features #237).

Добавлять не разом, а когда механизм трогаем — тогда же и enroll.
